# راهنمای استقرار روی GitHub Pages (Deployment Guide)

این مستند مراحل فعال‌سازی و استقرار پروژه **RTL Markdown Studio** را روی **GitHub Pages** شرح می‌دهد.

---

## ۱. روش پیشنهادی: استقرار خودکار با GitHub Actions (CI/CD)

پروژه مجهز به پایپ‌لاین خودکار در مسیر `.github/workflows/deploy.yml` است. با هر بار Push به شاخه `main` یا `master`، کد به طور خودکار بیلد شده و به عنوان سایت استاتیک روی GitHub Pages منتشر می‌شود.

### مراحل فعال‌سازی در گیت‌هاب (فقط یک‌بار):

1. به صفحه مخزن خود در **GitHub** بروید.
2. وارد تب **Settings** شوید.
3. از منوی سمت چپ، بخش **Pages** را انتخاب کنید.
4. در بخش **Build and deployment**:
   - گزینه **Source** را از حالت پیش‌فرض (Deploy from a branch) به **GitHub Actions** تغییر دهید.
5. کار تمام است! به تب **Actions** بروید یا یک کامیت جدید Push کنید تا پایپ‌لاین اجرا شود.
6. پس از اتمام اجرا، آدرس عمومی سایت شما در بخش Pages نمایش داده می‌شود (مثلاً `https://<username>.github.io/<repo-name>/`).

---

## ۲. روش دستی (اختیاری): استقرار مستقیم با ترمینال

اگر ترجیح می‌دهید پروژه را مستقیماً از سیستم خود بدون GitHub Actions بیلد و مستقر کنید:

```bash
# نصب پکیج‌ها (در صورت نیاز)
npm install

# اجرای بیلد ایستا و استقرار روی شاخه gh-pages
npm run deploy
```

> **نکته:** در صورت استفاده از این روش، در تنظیمات **Settings > Pages** منبع (Source) را روی **Deploy from a branch** و شاخه را روی **gh-pages** تنظیم کنید.

---

## ۳. ویژگی‌های فنی اعمال‌شده در این معماری

- **Export کامل استاتیک:** تنظیم `output: 'export'` و غیرفعال‌سازی هوشمند سرور بهینه‌ساز تصاویر (`images.unoptimized`) در زمان بیلد ایستا.
- **تطابق هوشمند ساب‌پث (`basePath`):** تشخیص خودکار مسیر زیرشاخه مخزن از طریق اکشن `actions/configure-pages`.
- **حل مشکل 404 در SPA:** خروجی صفحه اختصاصی `out/404.html` برای مدیریت خطای مسیرها.
- **فایل `.nojekyll`:** جلوگیری از مسدودسازی پوشه‌های سیستمی `_next/` توسط موتور پیش‌فرض Jekyll گیت‌هاب.
